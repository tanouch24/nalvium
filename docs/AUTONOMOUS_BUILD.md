# NALVIUM — COMMANDE AUTONOME CODEX\n\nCe document est destiné à être donné à Codex après installation du pack V2.\n\n## Mission\n\nConstruire NALVIUM V1 de bout en bout de manière autonome à partir de `SKILL.md` et de tous les documents `docs/`.\n\n## Composants\n\n- `app/` : Flutter Android/iOS ;\n- `backend/` : API, DB, médias, IA, safety, leads ;\n- `website/` : site public nalvium.com + SEO ;\n- `dashboard/` : administration leads/professionnels/contenu essentiel ;\n- `infra/` : développement/configuration sans création de ressource payante non autorisée.\n\n## Méthode\n\n1. Lire intégralement SKILL.md et docs/.\n2. Inspecter le repository existant.\n3. Résoudre les décisions techniques réversibles avec des choix standards, documentés et cohérents.\n4. Construire par phases sans demander de validation entre chaque phase.\n5. Après chaque phase : format, lint, tests, corrections.\n6. Continuer automatiquement jusqu'à V1 locale complète ou blocage externe réel.\n7. Pour une clé/service absent : créer l'interface, `.env.example`, mock/dev adapter, documenter, puis continuer.\n8. Mettre la documentation à jour si une décision d'implémentation est prise.\n\n## Exigences majeures\n\n### App\nOnboarding, accueil, caméra/galerie, preview, upload, analyse, clarification, diagnostic, guidage une action à la fois, nouvelle photo, vérification, résolution, pro, consentement, coordonnées, demande envoyée, historique, erreurs/permissions.\n\n### Backend\nSessions invitées, PostgreSQL/migrations, stockage média privé abstrait, diagnostics, repair steps, safety events, leads, professionnels, consentements, feedback, analytics.\n\n### IA\nProvider abstrait côté serveur. Pipeline : safety pre-check → multimodal → JSON strict → validation → safety post-check → persistance → next action. Mocks/fixtures obligatoires.\n\n### Safety\n`SAFETY.md` prime. La sécurité ne dépend jamais uniquement du LLM. Couche déterministe SAFE/CAUTION/STOP/EMERGENCY + tests de régression.\n\n### Leads\nPas de paiement, pas de marketplace complexe. Résumé + métier + zone + coordonnées + créneau + photos choisies + consentement + attribution simple.\n\n### Dashboard\nAuth admin, leads, détail, photos autorisées, résumé diagnostic, statuts, pros, zones, activation, métriques essentielles.\n\n### Website\nImplémenter `SEO_WEBSITE.md` : site public rapide, SSR/SSG, pages problèmes/guides/métiers/locales, metadata, canonical, sitemap, robots, structured data pertinente, breadcrumbs, maillage interne, règles indexable/noindex. Aucune génération massive de pages pauvres.\n\n### Privacy\nMédias privés, EXIF sensible supprimé lorsque nécessaire, consentements, suppression, analytics minimaux, pas de PII dans logs.\n\n### Tests\nAu minimum TESTS.md + tests unitaires, API, DB, Flutter, website, dashboard, safety regression, fixtures IA, E2E critiques. Ne jamais supprimer un test pour faire passer la suite.\n\n## Interdictions\n\nNe jamais :\n- push Git ;\n- déployer en production ;\n- publier Play/App Store ;\n- modifier DNS ;\n- acheter/créer une ressource cloud payante ;\n- exécuter une migration destructive distante ;\n- inventer des clés/secrets ;\n- contourner SAFETY.md.\n\n## Condition d'arrêt\n\nS'arrêter lorsque la V1 est exécutable localement, les composants communiquent, les tests pertinents passent, les règles safety sont couvertes, aucun secret n'est exposé, et qu'une build Android de recette peut être produite ou que les seuls blocages sont externes et clairement documentés.\n\n## Rapport final\n\nDonner :\n1. résumé construit ;\n2. architecture finale ;\n3. fichiers/modules principaux ;\n4. tests et résultats ;\n5. fonctionnalités fonctionnelles ;\n6. intégrations externes encore nécessaires ;\n7. blocages/TODO ;\n8. commandes exactes pour lancer app/backend/website/dashboard ;\n9. état build Android ;\n10. audit sécurité/privacy ;\n11. git status ;\n12. prochaines actions avant publication.\n\nAucun push ni déploiement.\n
