# NALVIUM — SITE PUBLIC & SEO\n\n## 1. Rôle\n\nLe site public `nalvium.com` est une composante produit V1. Il ne s'agit pas d'une landing page décorative : il doit capter une intention de dépannage, apporter une réponse utile et conduire vers le diagnostic NALVIUM ou, lorsque nécessaire, une demande de professionnel.\n\n## 2. Intentions de recherche\n\n### Problème / dépannage\nExemples :\n- fuite sous évier ;\n- chasse d'eau qui coule ;\n- robinet qui goutte ;\n- lave-linge ne vidange plus ;\n- lave-vaisselle code erreur.\n\n### Métier local\nExemples :\n- plombier Lyon ;\n- plombier Paris ;\n- réparateur électroménager Lyon ;\n- dépannage plomberie Lyon 3.\n\n### Information / guide\nExemples :\n- comment identifier une fuite ;\n- que vérifier avant d'appeler un plombier ;\n- comprendre un code erreur appareil.\n\n## 3. Architecture URL initiale\n\n```text\n/\n/comment-ca-marche\n/depannage/\n/depannage/plomberie/\n/depannage/fuite-sous-evier/\n/depannage/chasse-eau-qui-coule/\n/electromenager/\n/guides/\n/plombier/\n/plombier/lyon/\n/plombier/paris/\n/reparateur-electromenager/lyon/\n```\n\nLes slugs sont des exemples, pas une obligation de publier toutes les combinaisons.\n\n## 4. Règle programmatique fondamentale\n\nLe système peut générer des pages depuis des données structurées, mais une URL n'est indexable que si elle apporte une valeur suffisante.\n\nInterdit :\n- milliers de pages ville × métier identiques ;\n- texte simplement reformulé avec le nom de la ville ;\n- faux professionnels ;\n- faux avis ;\n- fausse disponibilité ;\n- faux prix locaux ;\n- pages sans contenu ni offre réelle.\n\nPrévoir un statut `indexable` contrôlé par qualité/contenu/couverture. Sinon `noindex` ou absence de génération.\n\n## 5. Template page problème\n\n1. réponse courte à l'intention ;\n2. signes/causes possibles formulés prudemment ;\n3. vérifications sûres ;\n4. signes nécessitant STOP/pro ;\n5. CTA « Montrez-nous le problème » ;\n6. FAQ réellement utile ;\n7. liens vers problèmes connexes ;\n8. possibilité de demander un professionnel lorsque pertinente.\n\nLe contenu ne doit jamais contourner SAFETY.md.\n\n## 6. Template page locale métier\n\n1. H1 métier + zone ;\n2. aide immédiate NALVIUM ;\n3. problèmes du métier ;\n4. informations locales réellement disponibles ;\n5. professionnels/couverture uniquement si données réelles ;\n6. fonctionnement de la demande ;\n7. FAQ locale utile ;\n8. CTA diagnostic / demande pro.\n\nNe jamais promettre un délai d'intervention sans donnée réelle.\n\n## 7. Technique SEO\n\nObligatoire :\n- rendu SSR/SSG adapté ;\n- title/meta uniques ;\n- canonical ;\n- sitemap(s) ;\n- robots.txt ;\n- breadcrumbs ;\n- données structurées pertinentes et conformes au contenu visible ;\n- URLs propres ;\n- 404/redirects propres ;\n- maillage interne ;\n- images optimisées ;\n- Core Web Vitals ;\n- Open Graph ;\n- analytics ;\n- Search Console après déploiement.\n\n## 8. Données structurées\n\nUtiliser uniquement les types réellement justifiés par la page. Ne pas ajouter de données structurées trompeuses pour tenter d'obtenir un rich result.\n\n## 9. Contenu\n\nLe contenu peut être assisté par IA mais doit être fondé sur des règles éditoriales et de sécurité. Les pages critiques doivent pouvoir être revues/éditées dans une source structurée ou CMS léger.\n\n## 10. Conversion\n\nCTA principal : **Montrez-nous le problème**.\n\nFunnels :\nSEO problème → diagnostic → résolution ou pro.\nSEO local → diagnostic ou demande pro → lead.\n\n## 11. Données SEO dans le dashboard\n\nÀ terme :\n- pages ;\n- statut indexable/noindex ;\n- métier ;\n- ville ;\n- problème ;\n- contenu ;\n- CTA ;\n- date mise à jour.\n\nPas besoin d'un CMS complexe pour la première V1.\n\n## 12. Lancement initial\n\nCommencer avec un ensemble limité de pages fortes : accueil, fonctionnement, catégories, problèmes principaux, guides et quelques zones réellement couvertes. Étendre après mesure des impressions, clics, diagnostics et leads.\n
