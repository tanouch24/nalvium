# NALVIUM — UX / UI

## Direction

Mobile, premium, extrêmement simple. L’utilisateur peut être stressé et avoir les mains occupées.

Règles :
- gros contrôles tactiles ;
- une action principale par écran ;
- texte court ;
- possibilité de réponse vocale plus tard ;
- progression visible ;
- photos privilégiées au long texte ;
- jamais de jargon sans explication.

## Navigation V1

### 01 — Splash
Logo NALVIUM. Chargement bref.

### 02 — Onboarding
Maximum 3 écrans :
1. Prenez une photo du problème.
2. Nalvium vous guide étape par étape.
3. Si c’est risqué ou impossible, trouvez un professionnel.

CTA : **Commencer gratuitement**

Mention claire : Nalvium ne remplace pas un professionnel qualifié.

### 03 — Accueil

H1 : **Qu’est-ce qui ne fonctionne pas ?**

CTA principal :
**Prendre une photo**

Secondaire :
- choisir depuis la galerie ;
- décrire le problème ;
- historique.

Catégories visibles en aide, pas comme obligation.

### 04 — Capture
Caméra avec :
- flash ;
- galerie ;
- conseil de cadrage ;
- bouton capture.

Après capture :
**Utiliser cette photo / Reprendre**

### 05 — Analyse
Animation courte.
Messages :
- « J’examine ce que vous m’avez montré… »
- ne jamais simuler une précision inexistante.

### 06 — Question complémentaire
Une question à la fois.
Réponses rapides + texte/photo si nécessaire.

Exemples :
- « La fuite apparaît-elle uniquement quand l’eau coule ? »
- « Pouvez-vous photographier l’étiquette avec la référence ? »

### 07 — Diagnostic / orientation

Blocs :
- Ce que j’observe
- Cause probable
- Niveau de prudence
- Ce que nous allons vérifier

CTA :
**Me guider**

Si risque :
**Mettre en sécurité / Appeler un professionnel**

### 08 — Réparation guidée

Une étape à la fois.

Chaque étape :
- numéro ;
- instruction courte ;
- illustration/photo annotée si disponible ;
- précaution ;
- CTA **C’est fait** ;
- **Je ne vois pas / Ça ne correspond pas / J’ai besoin d’aide**.

L’utilisateur peut ajouter une photo à tout moment.

### 09 — Vérification

Question :
**Est-ce que le problème est résolu ?**

Oui → succès.
Non → nouvelle analyse ou orientation pro.

### 10 — Succès

« Parfait. Le problème semble résolu. »

Actions :
- noter l’aide ;
- conserver dans historique ;
- terminer.

Ne pas affirmer qu’une réparation est définitivement sûre si cela ne peut pas être vérifié.

### 11 — Besoin d’un professionnel

Résumé :
- métier recommandé ;
- problème ;
- urgence indicative ;
- informations qui seront transmises.

CTA :
**Trouver un professionnel**

### 12 — Consentement lead

Afficher explicitement :
- données transmises ;
- photos sélectionnées ;
- téléphone ;
- zone ;
- description.

Checkbox/consentement explicite.

### 13 — Coordonnées et disponibilité
Prénom, téléphone, code postal/ville, créneau souhaité.

### 14 — Demande envoyée
Statut clair.
Ne pas promettre qu’un artisan est disponible tant qu’aucun ne l’a accepté.

### 15 — Historique
Sessions passées, statut, date, catégorie.

## États transverses

Prévoir :
- permission caméra refusée ;
- photo inexploitable ;
- réseau absent ;
- IA indisponible ;
- upload échoué ;
- analyse incertaine ;
- aucun professionnel disponible ;
- session interrompue/reprise.

## Accessibilité

- contrastes WCAG raisonnables ;
- taille texte dynamique ;
- labels lecteurs d’écran ;
- ne pas coder l’urgence uniquement par couleur ;
- vibration/son facultatifs.
